# v0.2.0 QA・失敗原因と修正

## 検証の範囲

第0章、工場の第1〜4話、新しい動物保護施設の第5話を同じ通常版でテストする。ChromiumとWebKitモバイル、390×844 CSS px、320px、本文28px相当の拡大を含む。iPhone実機は未確認。

単体テストは既存62件＋第5話9件＝71件。第5話のE2Eは10ケース×2ブラウザ。実画素・固定フィルタ・模式図・保存・復元・旧データ・オフラインを含む。

## 実計算の照合

- PNGを別のCanvasで32×32へ縮小して読み取り、画面Canvasの全4096チャンネル値と一致することを確認。
- 画素を選択すると、その座標のRGB値・色見本が元データと一致する。
- PNGを8×8へ縮小した明るさから、固定フィルタの最初の位置をテスト側でも別に計算。左右の変化・平均の両方で画面と一致する。
- 単体ではフィルタの全36出力を独立した二重ループで照合し、一定画像・不正入力も確認。
- ニューラルネットワークの図は模式図であると表示し、猫犬分類の計算結果や学習済みという実行結果を作っていない。

## 初回の失敗と原因

最初の追加E2Eは16件成功・4件失敗。次の追加確認は18件成功・2件失敗。失敗をタイムアウト延長や自動再試行で隠していない。

1. ホームのボタンを完全一致で「3分で全体像を見る」と指定していたが、実際のアクセシブル名には末尾の「↗」がある。画面スナップショットでボタンが表示されていることを確認し、テストの名前指定を修正した。待ち時間を増やしても一致しない、決定的な指定ミスだった。
2. D05の折りたたみ内に、計算式の追加折りたたみがある。子孫のsummaryすべてを指定したため2要素に一致していた。対象の直下のsummaryに限定した。
3. フィルタ選択欄はlabelの内側にselectを含めており、テストが想定する単独のラベル名に一致しなかった。HTMLを明示的なfor/idの関連付けへ修正し、選択欄の名前を「固定フィルタ」にした。単に待機時間を増やすのではなく、画面側のラベルを明確にした。

関連する深掘り・320px・文字拡大を両ブラウザで再確認し、6件すべて成功（57.8秒）。タイムアウト45000ms、1 workerを維持し、自動再試行は追加していない。

## 前回までの不安定要因との関係

v0.1.9で整理した、1ケースに長い本編・多数のPNG保存・完了後の任意演習までまとめる負荷を増やしていない。既存L003の本編完了と任意演習の再開は分けたまま。CLIで2 workerへ上書きしていない。

第5話も、主な物語、画素の照合、再開・一時停止、バックアップ、問題、深掘り、表示サイズ、オフラインを別ケースにした。画像は読み込み成功を待って保存し、固定sleepで進めていない。自動表示の確認は現在の段階を待ってから一時停止する。

## 最終結果

単体71件、全体E2E130件がすべて成功。Chromium 65件・WebKitモバイル65件、再試行0件、全体7.6分。最長ケースはWebKitの既存9場面の確認で11.190秒（Chromiumの最長7.306秒）。45000msの上限を延長していない。ケースごとの実時間・再試行回数・PNG保存回数と合計時間をperformance-v0.2.0.jsonへ保存した。

通常版とメニュー版のTypeScript検査・ビルドは成功。29ファイルの一覧・全バイトが一致し、メニュー版でもL005・L006・L007を390pxで完了した。
